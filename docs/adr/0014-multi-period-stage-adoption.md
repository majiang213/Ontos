# 多段时期：第二次生命周期判定采纳既有 status，不再撞名拒绝

## 背景

生命周期判定（`decide` 的 `stage`）把两类收成一个对象并立时期派生属性 `status`：两条来源规则（A 源有行 → 早段，B 源并进来的源有行 → 晚段）+ 一条转化关系 + 一个转化动作。

走查剧本（ADR 0012）里设备的时期有三段：在途（采购条目）→ 在役（台账）→ 已处置（处置档案）。第二段时期判定发生在已并类的对象上——它已经有带派生规则的 `status`。原实现一律抛 `stageStatusClash`（"已有同名字段，先改名或删掉"），而编辑通道（`edit_stages` 只能整份替换现有条目，条数不变；`add_property` / `update_property` 不带派生规则；`replace_object` 对已发布或含派生/动作/多源的类拒绝）没有任何办法把派生规则加回去——三段时期的世界用现有工具构不出来。

## 决定

`applyVerdict` 的 Stage 分支区分两种情形：

- **存活类已有带派生规则的 enum `status`**（并前先取，B 的状态列拷贝不算）：**采纳**。新源就是新的一段——规则前插（先命中先赢：新源有行 → 新晚段），取值缺就补（`to` 词；占位词带兜底中文名，其余由改标识补中文）。转化关系与转化动作照常各立一套（`${类}_to_${晚段}`）。
- **存活类没有 status，或那只是 B 拷进来的普通状态列**：维持原纪律——普通状态列是数据不是时期，让人先改名让位（如台账状态列改 `mark`），`stageStatusClash` 照抛。

判定入参的 `stage_names.from` 是被离开的时期（转化关系的 from），`to` 是新段。

## 影响

- 判定域测试钉两条：多段采纳（三值三规则两转化）与状态列让位（`stageStatusClash` 仍抛）。
- 走查剧本的处置对从「建链」改回「生命周期接续」（纠错清单决定 5 的落地）：处置档案行=个体的已处置时期，一一对应，进"同一概念"判定。
- 发布闸、问数、动作不受影响：采纳后的配置与手工建模的形状一致（先命中先赢的派生规则列表）。
