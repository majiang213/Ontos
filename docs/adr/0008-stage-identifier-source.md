# 时期标识的来源与兜底：现成值域原样取词，占位词 early/late 单源

生命周期裁决落地时，时期名会写进值域取值、派生规则、转化关系名与动作名——错词不是显示问题。曾有一段时间时期名来自写死的领域词：两条整合建议提示词枚举「设备 in_transit / in_service，人 candidate / employed」，离线回退给每对硬编码设备词，引擎兜底 `executionPlan` 也回退同一套词；同一「缺词兜底」不变量在 `executionPlan` 与 `applyVerdict` 各有一份、两套答案（后者兜底成「类名_前」这类中文 key）。任何非设备/人的空间做生命周期裁决，设备词整套进配置，问数与动作字面量跟着错。

决定：

- **时期名是建议的产出，判据是「原样取自两类现成枚举值域的取值（早→晚），不许新造词」**。建议输入带每类的枚举取值 key（`enums`）；没有可取的现成取值就整个省略 `stage`。Agent 依证据执行：留下谁、谁早谁晚、时期名都按建议与数据落，人审画布、可指令推翻。
- **兜底单源在 `executionPlan`**：缺词时用领域中性的占位 key `early` / `late`（中文名「早期 / 晚期」，落地值域带 label）。`applyVerdict` 不再自备兜底，「类名_前 / 类名_后」退役。
- **离线回退只产召回倾向**：没有语义可读，不产时期名、不猜谁早谁晚；状态类列名只当列表层的召回偏置（生命周期 vs 部分重叠的倾向），不是生命周期判据。
- **裁决卡显示将落地的词**：建议词或「占位词（可改标识）」；错词由「改标识」级联纠正（值域、派生规则、转化关系、动作前置一起改）。

被否选项：模型自由造词（词无锚，对不上任何配置）；缺词就拦裁决（打断「人只点关系类型」，0 行源表这类场景被卡死）；兜底沿用演示域设备词（任何领域都是错词）；离线回退喂值域取词（其草稿无值域，等于死代码）。
