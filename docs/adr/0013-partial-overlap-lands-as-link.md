# 同一概念的表并成一个多源类；不同概念之间用领域谓词链

## 背景

部分重叠裁下去会立一个"公共对象"：同名公共属性移上去，没有同名就只带唯一性标准（ADR 0001）。当两类的公共属性只剩唯一键本身时，它退化成一个单字段对象——不承载公共语义，只是一个对齐点，名不副实（真实案例：`po_item` × `asset` 的公共部分只有 `sn`，长出 `shared_po_item_asset`，只有一个字段）。

参照 Palantir Foundry 本体论的概念划分：object type 各自独立，类型之间的"指向"用 link type 表达，实体归一发生在数据管道层、不在本体层——"合并两个对象类型"与"为公共部分另立类型"都不是本体层的动作。

## 决定

**同日再修订（判定归 LLM 后的最终口径）**：判定只剩一个问题——"这两份是不是同一个概念？"

- **是**：一个对象类型**挂全部源**（多源类），行按唯一性标准对齐；时期语义用派生属性表达（按来源有无行派生 在途/在役）。来源覆盖面不同（部分重合、子集）只是多源类的数据事实，不是结构选择——不存在"部分重叠"这种独立的落地情形。
- **不是**：两类各自独立。一方字段指向另一方个体的（如工单的序列号指向设备），建一条**带领域谓词的 match 链**（Agent 起名，照附录 C 形状如 `on_equipment`；起不出领域名的链不建）。

`class_conclusions` 不再写入；结论与证据住 `adj_decision`。历史草稿里已立的 shared_ 对象与带 shared 的结论照旧渲染（虚线「公共部分」），不迁移。

（本 ADR 因此先后取代：ADR 0001 的落地段、本文早先"部分重叠自动建 match 链"的版本。）

## 影响

- 判定段不变：部分重叠的判定仍只看个体在同一性标准下的重合（ADR 0001 的判定段继续成立），本决定只取代其落地段。
- 部分重叠不再触发公共属性上移，也就不再有 set_fields 摘键；`commonProperties` 资格辅助随之删除。
- `sharedObjectName` / `isSharedObjectName` 保留，唯一用途是历史草稿的渲染与识别。

（本研究与决定由 Palantir Foundry 本体论对照分析触发，对照材料见 `docs/research/palantir-foundry-ontology-vs-ontos.md`。）
