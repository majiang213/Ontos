# 设计文档中的废旧概念清单

> 研究范围：2026-09-30。本文只列问题，不修改被扫描的文档。判定依据按优先级取：根目录 `CONTEXT.md`、仍有效的 ADR（含修订注记）、代码当前执行的行为。`docs/adr/0006` 与 `0012` 中被 2026-09-01 修订注记废掉的原决定，按旧说法处理。
> 状态：这是清理前的审计底稿。后续修订已处理其中的现行性冲突；本文件保留原出现位置、依据和处置理由，不能当作当前规格。

## 现行基准

- `CONTEXT.md`：类与类的关系不是封闭清单；部分重叠的同一概念表并成一个多源类；不同概念之间才建带领域谓词的 `match` 链；裁决结论与证据不进本体配置；问数时的“对齐”是按同一性标准把各源行配成同一个体。元库的候选、交集、裁决存储分工以代码和有效 ADR 为准：`adj_candidates`、`adj_overlap`、`adj_decision`。
- `docs/adr/0006-class-conclusions.md:5`：2026-09-01 修订已废止“结论写入 `class_conclusions`”和“部分重叠另立公共对象”；历史行仍兼容渲染。
- `docs/adr/0013-partial-overlap-lands-as-link.md`：有效落地口径是同一概念并为多源类，不抽公共对象；不同概念的关联才进 `link_types`，且链要有领域语义。
- 代码现行行为：元库按职责使用 `adj_candidates`、`adj_overlap`、`adj_decision` 保存候选、交集和新裁决；画布优先读取工作记录，并对旧草稿的 `class_conclusions` / `shared_` 做兼容投影；配置 schema 和部分读路径仍保留旧键以支持历史草稿。查询引擎按 `identity` / 源条目的 `key` 对齐行。相关登记见 `AGENTS.md`“纪律单一住所”与 `src/server`、`src/features` 中的这些工作记录和 `identity` 引用。

## 需要改写或删除的现行性表述

### 1. 把类关系收成封闭清单

- 旧概念：类与类只有固定的“四类/五类结论”，或把“跳过”也算一种关系。
- 出现位置：
  - `docs/ontology-reference.md` §3.2 “本体对齐”原文仍写“对候选对的判定是封闭的几项”。同节后文又写“可以判定为类等价、部分重叠、生命周期或同形异义。也可以跳过”。
  - `docs/adr/0012-test-scenario.md` 标题/分布行“10 对候选、四类裁决齐全”（修订注记已明确废止）。
  - `.scratch/palantir-alignment/design.md:44` “五项类间结论”。
- 现行出处怎么说：`CONTEXT.md` 与 `AGENTS.md` 明确禁止对类关系计数；类关系不是封闭清单。能落地的关系逐个点名，子类型、部分与整体、不相交本期不定案；跳过是动作，不是关系。有效 ADR 0006 也明确同样口径。
- 处置建议：改成现行说法。`docs/adr/0012` 的旧分布只保留为历史注记，不得再当剧本规格；`.scratch` 的设计分析应标为历史决策材料或删除旧结论句。

### 2. 把“上位对象/公共对象”当成当前落地

- 旧概念：部分重叠时抽出公共部分，另立上位对象，公共属性上移。
- 出现位置：
  - `docs/adr/0005-pairs-belong-to-a-chain.md` “裁部分重叠后……新立的公共对象算进这一串”。
  - `docs/adr/0006-class-conclusions.md:7` “类型级结论不进 `link_types`”及旧的公共对象投影规则。
  - `.scratch/palantir-alignment/ontology-error-inventory.md` 对 MVP §2、§4、附录 A/B 和走查文档的旧落点汇总。
  - 任何仍把“上位对象”写成部分重叠当前结果的设计段落。
- 现行出处怎么说：`CONTEXT.md`“多源归并与关联链”、ADR 0013、旧 MVP 设计稿第 36 行、`docs/ontology-reference.md:121`：同一概念的表并成一个多源类，一个对象挂全部来源；不抽公共对象。不同概念之间才按领域语义建 `match` 链。
- 处置建议：改成现行说法。旧 MVP 设计稿第 489 行的“上位对象（已废）”只作为历史依据保留在本审计和现行兼容说明中，旧稿本身不再作为文档入口。

### 3. 把“待确认”当成现在的入口或人工关卡

- 旧概念：用户在“待确认”面板逐条确认唯一键和疑似重复，并选择五种裁决。
- 出现位置：
  - `.scratch/palantir-alignment/spec.md:53` 已写退场，但同一 spec 仍把“待确认”作为页面形态描述。
  - `.scratch/palantir-alignment/design.md:152` 的旧方案标题“待确认按钮 + 裁决面板”。
  - `docs/真模型端到端测试.md` 中以“第一波要裁的候选”“待确认全部定案”为前提的旧段落（若该文件仍有这些句子，应按此项处理）。
  - `AGENTS.md` 当前仍把“待定卡/待定入口”列为 UI 结构；它同时明确判定归 Agent、待定项只读，这里是“入口”概念未完全收敛的问题。
- 现行出处怎么说：`CONTEXT.md`“对齐判定”与 `AGENTS.md`：判定是 Agent 内部步骤，不设按钮；疑似重复只读展示，只有有待定项才显示；人审画布并通过对话指令纠正，发布由人点。有效 ADR 0012 修订注记也说多数表级候选不再出现，清单仅作历史对照。
- 处置建议：改成现行说法。若段落是在记录迁移历史，可保留并明确“已退场/历史对照”；若把它写成操作步骤或当前页面入口，则可删或改。

### 4. 用一个“留痕”概念混合裁决留痕与动作留痕

- 旧概念：把“每次裁决、问数、动作”都笼统写成同一类留痕，或说裁决结论与本体一起进入同一事实源。
- 出现位置：
  - `README.md:31-32`、`:86`、`:119` 的“结论与证据留痕/每次问数与动作留痕”未区分记录归属。
  - 旧 MVP 设计稿第 27 行“护城河 = 裁决知识库 + 映射资产 + 血缘”以及动作/查询记录段落，需检查是否把它们写成同一记录。
  - `docs/ontology-reference.md` 中把“裁决工作记录”和动作日志并称“留痕”的段落。
- 现行出处怎么说：候选快照、交集证据、裁决结论及证据快照分别住元库 `adj_candidates`、`adj_overlap`、`adj_decision`，不可重算；动作执行留痕属于 `log_action`/动作结果；问数不留业务台账，验收问题集另有元数据。
- 处置建议：改成现行说法。若是介绍产品能力，可以保留“留痕”这个总称，但必须写明记录类型和住所；涉及配置时必须改为“裁决留痕不进 YAML”。

### 5. “对齐”同时承载两层不同含义而未加限定

- 旧概念：同一个“对齐”既指候选类之间的对齐判定，又指查询时把不同源的行配成同一个体。
- 出现位置：
  - 旧 MVP 设计稿第 31、57、86、92 行的类间“对齐判定”和查询/跨源对齐。
  - `docs/ontology-reference.md:112`、`:312` 的本体对齐，与 `:592`、`:1308` 的多源查询对齐。
  - `README.md:85`、`:180` 的“跨源对齐”。
- 现行出处怎么说：`CONTEXT.md`把两者分开：对齐判定是 Agent 对候选类作现实语义判断；问数/动作中的对齐是按同一性标准，把不同源的行配成同一个体。唯一键是三处共用的属性，但动作不同，不能用一个未限定的“对齐”代替两层。
- 处置建议：改成现行说法。类场景写“类与类的对齐判定/裁决”；查询场景写“按同一性标准把各源行配成同一个体”或“多源取数对齐”。

### 6. 把部分重叠写成“公共对象”或只有一条无语义 match 链

- 旧概念：部分重叠不是并成多源类，而是保留两类、另立公共对象；或把结果概括成“一条 match 链”而不要求领域谓词。
- 出现位置：
  - `docs/adr/0001-partial-overlap-not-same-name.md` 的旧落地段（若被正文引用，应标旧决定）。
  - `docs/adr/0005-pairs-belong-to-a-chain.md`、旧版 ADR 0006。
  - `.scratch/palantir-alignment/ontology-error-inventory.md:102-103, 117-130, 201-202` 的旧规格摘录。
  - 任何仍写“自动按唯一键建 match 链”但没有“不同概念/领域谓词”限定的段落。
- 现行出处怎么说：ADR 0013、`CONTEXT.md`：同一概念表并成一个多源类；不同概念之间才建带领域谓词的 match 链，起不出领域名的链不建。
- 处置建议：改成现行说法。旧 ADR 及纠错清单中的原句可保留作为“已被 0013 取代”的历史依据；不能继续被引用为当前设计。

### 7. 把 `class_conclusions` 写成现行配置键

- 旧概念：本体根列表有 `class_conclusions`，其中 `kind: overlap` 必须写 `shared`；画布从该配置投影裁决徽章/虚线。
- 出现位置：
  - `docs/adr/0006-class-conclusions.md:5-7`：第 5 行已废止原决定，但第 7 行仍保留旧规则，容易被误读为现行。
  - `.scratch/palantir-alignment/ontology-error-inventory.md:122, 128-131, 205-206` 的旧附录/登记处描述。
  - `AGENTS.md` 交互架构段落中“历史草稿的 shared_ 公共对象仍按 `class_conclusions`……渲染”——这是兼容行为，不是新配置规范。
- 现行出处怎么说：`CONTEXT.md`、ADR 0006 修订注记、代码现行行为：新候选/交集/裁决分别写 `adj_candidates`、`adj_overlap`、`adj_decision`，本体配置不含 `class_conclusions`；旧草稿仍读取旧行并渲染 `shared_`，以保证历史空间可打开。
- 处置建议：现行规格段落改写并删除新配置键的要求；兼容说明必须留下，理由是历史草稿还要渲染。附录 B/C 的旧键说明若确实是“完整已发布文本/保留字历史兼容”内容，先不要删键，标注为兼容/历史形状，不能把它当新增配置骨架。

## 还需单独标注的旧词，不要误删

| 旧词/形状 | 处理 | 必须留下的理由 |
|---|---|---|
| `shared_` 公共对象 | 必须留下兼容说明；新规格不得再生成 | 历史草稿按旧结论渲染，代码仍需兼容读取 |
| `class_conclusions` | 必须留下迁移/兼容说明；不得作为新配置键 | 历史草稿的画布投影仍依赖旧行 |
| 附录 B 的键、保留字、命名空间；附录 C 的完整 YAML | 必须留下，不建议删除 | 它们是配置骨架和已发布实例；用户明确要求不删 |
| `adj_candidates` / `adj_overlap` / `adj_decision` | 必须留下 | 分别保存候选快照、交集证据、现行裁决及证据快照 |
| 动作留痕（`log_action` 等） | 必须留下并与裁决留痕分开 | 这是执行审计，不是类间裁决记录 |
| “上位对象（已废）”条目 | 必须留下，但只作历史词条 | 解释旧草稿和旧文档为什么出现 `shared_`，防止把兼容形状误当现行设计 |

## 结论

当前最容易造成误读的不是单个禁词，而是把“判定、落地、工作记录、查询执行”压成一层。所有目标文档应统一到四条：类关系不是封闭清单；同一概念的表并成一个多源类；不同概念才建带领域谓词的关联链；候选、交集、裁决分别进 `adj_candidates`、`adj_overlap`、`adj_decision`，旧 `class_conclusions`/`shared_` 只为历史草稿兼容。查询章节中的“对齐”则必须加上“按同一性标准把各源行配成同一个体”的限定。
