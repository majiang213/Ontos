# 文档地图

本文档只负责导航，不重复定义产品概念、配置键或实现规则。遇到冲突时，按下表的“职责”找唯一出处。

## 先读什么

1. [根目录 README](../README.md)：项目是什么，以及如何启动。
2. [CONTEXT.md](../CONTEXT.md)：领域概念、术语和本体论边界的唯一出处。
3. [AGENTS.md](../AGENTS.md)：仓库工作规则、UI 用语、配置纪律和代码边界。
4. [系统架构](system-architecture.md)：产品边界、模块、元库、工作空间和部署形态。
5. [本体参考](ontology-reference.md)：配置语言、查询、动作和完整配置骨架。
6. [真模型端到端测试](真模型端到端测试.md)：从接入到问数、动作的走查剧本。
7. [ADR](adr/)：需要知道某个设计为什么这样定时，再读相关决定。

### ADR 清单

当前共有 14 份决定记录：

- 0001–0002：部分重叠和结论判定不看名字、表结构。
- 0003–0005：判定办法、候选串和未完成的历史边界。
- 0006：裁决留痕住工作记录，配置只收本体结构。
- 0007–0010：动作表单、时期标识、LLM 接口和唯一键。
- 0011–0012：画布布局和 `test` 空间走查剧本。
- 0013：同一概念的表并成一个多源类，不抽公共对象。
- 0014：多段时期沿用已有 `status`。

读 ADR 时先看文件顶部的状态/修订注记；有效口径仍须回到 `CONTEXT.md` 和代码核对。

## 历史资料和工作记录

这些文件可以解释“为什么改过”，但不能作为当前规格直接引用：

- [research/](research/)：外部资料核对、提示词审计和废旧概念审计。
- `.scratch/`：临时规格、拆分任务和实现问题单。它是工作记录，不是发布文档；其中的 `shared_`、`class_conclusions` 等旧形状只在兼容说明明确要求时保留。

历史材料中的旧术语可以原样出现，这是为了保留证据；写新规则时不要从历史材料反推现行说法。

## 文件归属规则

- 产品/系统问题写 `system-architecture.md`；配置键或请求形状写 `ontology-reference.md`。
- 新概念先改 `CONTEXT.md`，设计取舍再新增或修订 ADR。
- 操作步骤写走查文档或对应 `skills/*/SKILL.md`，不要塞进概念定义。
- 临时方案和实现拆解放 `.scratch/<feature>/`；完成后只把稳定结论回写到现行文档。
