## 作品名称

**Ontos（安托斯）——本体论驱动的现有数据库 AI 读写中间层**

## 作品链接

https://tabula-rasa-initiate.mynocode.host

## 作品简介

同一台设备，在采购、台账、资产三个系统里是三个名字。它们是不是同一个？Ontos 把本体论工程化：机器可读的本体覆盖在现有数据库之上，规定什么存在、何时同一；交集率当证据，由人定案。接入只加配置不加代码，问数、写回都按本体执行。不搬一行数据，每一步有定义、有证据、可回滚。

## 作品详情（全体可见）

### 问题定义：什么存在、何时同一

人工智能在企业业务中的落地，以数据语义的一致理解为前提，跨系统同一性是最基础的环节：同一设备在采购、台账、资产三套系统中标识不同，采购记"在途"、台账记"在役"。是否为同一对象、是否为同一对象的先后时期，数据层本身不提供判定依据。数仓迁移只复制数据，语义留在人工维护；模型直连把语义判断交给模型临场推断，两条路线都不建立机器可读的语义定义。Ontos 以本体建立该定义：规定什么存在、何时同一，交集率当证据、由人裁决，问数与写回按本体执行。

### 背景与问题

| 问题 | 市面方案的现状 | Ontos 的做法 |
|---|---|---|
| 数据迁移成本高 | 数仓 / 指标平台先复制数据再人工建模，周期以季度计，源头一改全链路同步；API 集成每系统一套适配器，老系统常无开放接口 | 不搬数据：配置直连（只读账号连接、源映射、动作定义），新系统只加配置不加代码 |
| 模型直连风险高 | Text-to-SQL 与数据分析 Agent 由模型直接编译 SQL、自主多步查询；无语义定义，幻觉 SQL 无法前置拦截 | 模型只产结构化查询，引用的类/属性/关系必须在已发布本体中；SQL 由引擎确定性编译 |
| 跨系统同一性无依据 | 检索问答（RAG）检索文档与元数据，与实时数据脱节；跨库语义靠模型临场猜，回答无取数路径可核验 | 本体规定同一性，交集率当证据、由人裁决；问数实时下推各源，答案附取数路径 |

**Ontos 的相对优势**：

- 语义唯一出处：本体（YAML 单一事实源）规定类、属性、关系与同一性，版本化发布、可回滚——市面方案中语义或人工维护、或散落适配器、或临场推断；
- 模型不当计算器：模型只建议（对象草稿、候选对、结构化查询），编译与执行是确定性代码；
- 读写一体：问数联邦下推附取数路径，写回只执行已发布动作定义，配置即权限边界；
- 人把关合并：涉及合并的裁决（类等价 / 部分重叠 / 生命周期）只由人定案，裁决与证据留痕可回滚。

### 设计路线：配置直连，而不是 API 集成

| 路线 | 做法 | 语义定义在哪 | 代价 / 边界 |
|---|---|---|---|
| 数仓 / 主数据 | 复制数据、ETL 加工后再治理 | 人工维护（ETL 与文档） | 周期以季度计；源系统一改，全链路同步；数据存两份 |
| API 集成 | 每系统一套适配器 | 散落在各适配器代码 | 老系统常无开放接口；适配器随系统数线性增长；语义各写各的 |
| 模型直连 | 模型直接生成 SQL 执行 | 每次查询临场推断 | 幻觉 SQL 风险；语义无一致定义，同一问题答案可能不同；写库等于交出编辑权 |
| **Ontos 配置直连** | 连接（只读账号）+ 源映射（属性→列）+ 动作定义 | 已发布本体，单一事实源 | 新系统只加配置不加代码；权限用数据库账号控制；取数路径可解释可审计；语义随版本可回滚 |

Ontos 的配置直连包含三项配置：连接（只读账号）、源映射（属性→列）、动作定义。问数与动作的 SQL 由引擎按本体确定性编译、按映射投影、按方言归一，下推源库执行；新系统只加配置不加代码。

### 方案：本体作为读写中间层

本体（YAML 单一事实源）定义领域的类、属性、关系与同一性标准，覆盖在全部现有数据库之上：

1. **什么存在**：本体只定义类（事物/事件、属性、关系），个体留在源库，平台不存业务行（类与个体分离）。
2. **何时同一**：每个类先定唯一键（同一性标准）；跨源识别以交集率当硬证据，由人裁决为类等价 / 部分重叠 / 生命周期 / 同形异义；模型建议只是软证据，裁决与证据快照留痕可回滚。
3. **变化中保持同一**：生命周期把同一体的先后时期（在途→在役→报废）建模为派生阶段字段，转化动作自动建立。
4. **同名与异实**：同形异义用于名字相似但指称不同的类（设备台账部门 vs OA 部门），结论写入配置，不产生合并。
5. **部分与整体**：本期不裁决（订单×条目、保修卡×设备），避免强行归类。

类等价、部分重叠、生命周期、同形异义、同一性标准均为本体论术语，在 Ontos 中落地为裁决动作与配置结构。

### 核心机制：先定义、后执行

平台的两条执行路径——问数（读）与动作（写）——遵循同一原则：先定义、后执行。模型只建议，执行由确定性代码完成；两条路径的细节见下节。

- **一致性**：问数与动作只读已发布快照；本体版本化发布，可回滚。
- **证据链**：模型建议（软证据）→ 交集率（硬证据）→ 人裁决（结论），涉及合并的裁决不开放给自动流程。

### 问数与动作：模型建议、引擎执行

| 路径 | 机制 | 效果 |
|---|---|---|
| 问数 | 模型只把自然语言编译为结构化查询（Zod 校验），不生成 SQL；引用的类/属性/关系必须在已发布本体中 | 模型编不了表名字段；SQL 由引擎确定性编译、按映射投影、方言归一、下推各源、应用层拼装，不搬数据不留台账 |
| 问数 | 答案附取数路径；跨源识别与问数共用同一唯一键 | 取数过程可查，判定标准一致 |
| 动作 | 定义 = 动作名/对象/唯一键/前置/效应（Zod）；写回目标由效应+来源映射推导，无表名 | 配置即权限边界，换源不改动作 |
| 动作 | 执行器解释已发布本体，禁自由 SQL；前置与公理校验不满足即拒 | 生成要模型、执行不要；非法请求在配置层被拦 |
| 动作 | create 幂等（唯一索引 + 冲突重查）；生命周期裁决自动立转化动作；复合变更 = 多效应 | 重发不落重行；裁决直接变可执行能力；不按行业写分支 |

### 使用流程

**demo 与源项目**：demo（https://tabula-rasa-initiate.mynocode.host）是源项目的纯前端静态演示，浏览器内运行完整引擎（内存元库 + 内存源库 + 演示剧本），无需部署、无需模型 Key；源项目是完整平台（Next.js 前后端一体），连接真实现有数据库、调用真实模型、对外提供 MCP 服务器。两者是同一产品、同一套引擎逻辑与界面，差异只在数据与模型来源：

| 项目 | demo | 源项目 |
|---|---|---|
| 运行形态 | 纯前端静态页 | Next.js 前后端一体 |
| 数据 | 内存源库（演示剧本） | 真实现有数据库（SQLite / MySQL / PostgreSQL） |
| 模型 | 演示剧本，无需 Key | 真实模型（OpenAI 兼容；未配 Key 时同样走演示剧本） |
| 外部接入 | 无 | MCP 服务器（十工具）+ 四个配套 skill |

**平台内五步**：

1. **连接数据源**：配置只读账号接入源库，读取表结构（类型/主键/注释 + 脱敏采样）。
2. **生成对象**：勾选表结构，模型建议业务对象与关系草稿上画布；建议只进草稿。
3. **裁决**：疑似重复对象进待确认面板（跨库或同库两张表）：先定唯一键、再算交集率，裁决为类等价 / 部分重叠 / 生命周期 / 同形异义，或跳过。
4. **发布**：对象、关系、动作与全部裁决合并为单一事实源，带版本号入库。
5. **问数与动作**：发布后，问数经外部 Agent 的 MCP 工具或站内问题集跑批；动作经 MCP 的 run_action 执行。人的关卡（选表、唯一键、裁决、发布）不开放给自动流程。

**外部 Agent 经 skill 驱动**：问数与动作的调用方是外部 Agent（Claude / Codex 等），在 Agent 侧配置 Ontos 的 MCP 端点（`/api/<空间名>/mcp`）并加载配套 skill：

| skill | 职责 |
|---|---|
| ontos-query | 问数：把自然语言编译为结构化查询并执行，返回结果与取数路径 |
| ontos-action-run | 执行已发布动作：验收入库、入职、转正等 |
| ontos-canvas | 读写画布：对象、关系、字段的查看与增改，生成对象建议 |
| ontos-action | 动作定义：用 set_action 定义新的业务动作（写入草稿，发布后生效） |

**示例链路**：接入采购、设备、资产三个库后，「在途设备」×「在役设备」交集率约 1/3，裁为生命周期；设备 × 资产全重合，裁为类等价。发布后 Agent 经 ontos-query 问「列出在役设备及其所属部门」，从三库实时拼装并附取数路径；经 ontos-action-run 跑「验收入库」，写设备源、资产源各一行并立保修卡，阶段变为在役。

### 安全与治理

- 平台元库不存业务数据列；问数只读查源库，日志不存结果集；交集比对在内存完成，取值集合算完即弃；
- 写入仅执行已发布动作定义，配置之外被引擎拒绝；表结构采样脱敏后进入界面；
- 问数用只读账号、动作另备可写账号，写端点可加 Bearer 令牌；问数与动作全程留痕，裁决附证据快照，历史版本一键回滚。
