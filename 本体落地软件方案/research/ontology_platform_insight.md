# 调研核心洞察（写作输入）

## 洞察 1：市场空白是"四能力交集"，不是单点创新
通用本体建模 + 存量系统映射改造 + Action 写回 + AI Agent 原生消费——四者各自有产品，但没有一款产品（尤其中文/国产化语境）把四者打通。产品定位应锚定这个交集，叙事为"AI 时代的本体底座/语义基础设施"。

## 洞察 2：Action（动作层）是与知识图谱划清界限的命门
知识图谱厂商（国内外）集体停留在"图谱构建+分析+问答"，无业务写回。Palantir 与微软（预览）是仅有的两家原生支持 Action 的厂商。必须把 Action 引擎做成一等公民，否则沦为又一个 KG 项目。

## 洞察 3：AI 辅助建模是对 Palantir FDE 模式的"成本革命"
Palantir 的 Ontology 落地依赖高价 FDE 人肉实施，且其平台 API 对本体定义多为只读（建模依赖 UI）。用 LLM 自动解析 schema/文档/业务描述生成本体草稿 + Ontology-as-Code（YAML/Git 化），能把实施成本压一个数量级，是面向中小企业的核心价值主张。

## 洞察 4：权限模型是"AI 可治理"故事的技术支点
Palantir 两层权限（schema 资源层 + 数据层）并经同一安全模型约束 LLM，被官方作为核心卖点。我们的权限模型必须做到对象/属性/Action 三级粒度，且 Agent 与普通应用走同一权限通道——"AI 只能做你被授权做的事"。

## 洞察 5：开源生态可大幅压缩自研成本
连接器（Airbyte/Singer）、GraphQL 自动生成含权限（Hasura/PostGraphile）、图存储（NebulaGraph）、指标语义（MetricFlow）、虚拟图谱（Ontop）——V1 应站在这些组件之上，自研集中在元模型、AI 建模、Action 引擎三个差异化模块。

## 洞察 6：标杆对手的弱点 = 我们的定位空间
Palantir：封闭、昂贵、绑定自有生态、数据须迁入索引；Fabric IQ：预览期、锁微软生态；国内 KG 厂商：无 Action、无 Agent 原生消费。我们的空间 = 开放（连接任意系统、数据可不搬家）+ 国产可私有化 + Agent 原生。
